# update-rules

Обновление базы знаний по итогам задачи. Обязательный шаг, не опциональный.

## Когда обновлять

База знаний ДОЛЖНА быть обновлена, если задача выявила:

- Конвенцию, которая нигде не описана.
- Ошибку, которой можно было избежать при наличии правила.
- Устаревшее или некорректное правило.
- Новое архитектурное решение или паттерн.
- Бизнес-логику, не описанную в правилах.

Если ничего из вышеперечисленного -- обновлять не нужно.

## Как обновлять

1. Определи область: проект-wide или конкретная поддиректория.
2. Обнови или создай файл правила в `.agents/rules/<name>.md`.
3. Добавь / обнови сводку со ссылкой в соответствующем `AGENTS.md`.
4. Если правило уже существует -- обнови его, не создавай дубликат.
5. Пиши кратко, с реальным примером из завершённой задачи.

## Правило одного перехода

Из любой записи в `AGENTS.md` полное правило должно быть достижимо ровно по одной ссылке.
Каждая сводка в `AGENTS.md` ДОЛЖНА ссылаться напрямую на файл правила.

Правильно:
```markdown
### Именование сущностей
PascalCase для типов, camelCase для локальных переменных.
[Подробности](.agents/rules/backend/general.md)
```

Неправильно:
```markdown
### Именование сущностей
Используется стандартный подход. Подробности в папке rules.
```

## Нет осиротевших файлов

Каждый файл в `.agents/rules/` ДОЛЖЕН иметь ссылку хотя бы из одного `AGENTS.md`.
При создании файла -- сразу добавить ссылку. При удалении -- убрать все входящие ссылки.

## Связь с do-review

Если задача выявила область кода, не покрытую ни одной валидацией в `do-review`,
создай `validate-<domain>.md` в `.agents/skills/do-review/` и зарегистрируй в
`do-review/SKILL.md` в Шаге 2.
