# Написание скилов и инструкций

Руководство по созданию Agent Skills и инструкций для AI-ассистентов.

## Ключевые принципы

1. Description -- это триггер: делай его подробным и конкретным
2. Прогрессивное раскрытие: сначала концепции, потом примеры
3. Чистый технический стиль: без эмодзи, минимум форматирования
4. Русский для пояснений, английский для кода и имён файлов

## Форматы файлов

### Agent Skills (`.agents/skills/`)

Скилы -- задача-специфичные навыки, загружаются по запросу агентом.

```yaml
---
name: skill-name
description: What the skill does and WHEN to use it. | Что делает скил и КОГДА использовать.
tags: []
author: username
version: "1.0.0"
scope: project
platforms: [claude-code, cursor, copilot]
---
```

### Инструкции Cursor (`.cursor/rules/`)

Always-on правила: кодстайл, архитектура, конвенции.

```yaml
---
description: Rule description. | Описание правила.
globs: src/**/*.cs
alwaysApply: false
---
```

Поля:
- `description` -- описание (для Cursor)
- `globs` -- glob-паттерн файлов, к которым применяется
- `alwaysApply: true` -- применять всегда (без globs)
- `alwaysApply: false` + без `globs` -- Cursor решает сам

### Инструкции Copilot (`.github/instructions/`)

Формат аналогичен Cursor, но `globs` -> `applyTo`:

```yaml
---
applyTo: "src/**/*.cs"
---
```

## Скилы vs. Инструкции -- когда что использовать

| | Инструкции | Скилы |
|---|---|---|
| Назначение | Кодстайл, архитектура, конвенции | Задача-специфичные процедуры |
| Когда активны | Всегда или по glob-паттерну | Агент решает сам по description |
| Примеры | "Используй primary constructors" | "Как создать новую фичу" |
| Размер | До 100 строк | До 500 строк + доп. файлы |

## Написание description для скилов

Description -- главный механизм активации. Агент читает все description при старте и решает, какие скилы загрузить.

Формат: английский текст, затем `|`, затем русский дубль.

```yaml
description: English description of what and when. | Русское описание что и когда.
```

Плохо:
```yaml
description: Помощь с git
```

Хорошо:
```yaml
description: Git branching and commit naming rules. Use when creating a branch or writing a commit message. | Правила именования веток и коммитов. Используй при создании ветки или написании коммит-сообщения.
```

Что включать:
- ЧТО скил делает
- КОГДА его использовать (триггерные фразы на обоих языках)
- Ключевые технологии/компоненты

## Структура скила

Простой скил -- всё в `SKILL.md` (до 500 строк):

```
skill-name/
└── SKILL.md
```

Сложный скил -- с дополнительными файлами:

```
skill-name/
├── SKILL.md              # Концепции, решения, когда/зачем
├── scripts/              # Исполняемые скрипты
│   └── check.sh
├── references/           # Детальная документация
│   └── REFERENCE.md
└── assets/               # Шаблоны, данные
    └── template.json
```

## Структура содержания

Паттерн "Дерево решений":
```markdown
## Какой тип задачи?

1. Тип A? -- см. Раздел A
2. Тип B? -- см. Раздел B
```

Паттерн "Пошаговый воркфлоу":
```markdown
## Шаг 1: Определить
## Шаг 2: Проанализировать
## Шаг 3: Реализовать
```

Паттерн "Справочник паттернов":
```markdown
## Паттерн 1: Название
Описание + пример кода

## Паттерн 2: Название
Описание + пример кода
```

## Самодостаточность скилов

Скилы должны быть самодостаточными:
- Не ссылаться на файлы за пределами папки скила
- Примеры -- внутри папки скила
- Если нужно сослаться на внешний документ -- скопировать релевантную часть

## Частые ошибки

### Ошибка 1: Слабый description

Проблема: описание слишком общее, скил не срабатывает когда нужно.
Решение: включить конкретные технологии, названия компонентов, триггерные фразы.

### Ошибка 2: Весь код в SKILL.md

Проблема: SKILL.md разрастается до 500+ строк из-за примеров кода.
Решение: вынести примеры в `EXAMPLES.md` или `references/`.

### Ошибка 3: Нет анти-паттернов

Проблема: показан только правильный путь, без объяснения типичных ошибок.
Решение: показать реальные ошибки, объяснить почему неправильно.

## Проверка перед коммитом

1. Description триггерится на нужные запросы
2. YAML frontmatter валиден
3. Ссылки между файлами скила работают
4. Нет эмодзи
5. Прочитать как будто видишь впервые -- понятно ли?
